## ML_Homework_reranker
# Ранжирование русскоязычных результатов поиска

Jina Reranker v2 и CatBoostRanker оценивают каждый фрагмент. Итоговый скор — взвешенная сумма этих двух оценок. Веса подбираем по разметке из `train.csv`.

## Запуск

Положите `train.csv`, `test.csv` и `sample_submission.csv` рядом с `solution.ipynb` или в папку `data/`. Имена вроде `train (19).csv` тоже подойдут. Другой каталог можно указать через `PMMO_DATA_DIR`.

```bash
python3.12 -m venv ../pmmo-venv
source ../pmmo-venv/bin/activate
python -m pip install -r requirements.txt
```

Запустите все ячейки ноутбука в этом окружении. При первом запуске он скачает ONNX-модель и токенизатор Jina (около 300 МБ) и сверит контрольные суммы. Результат появится в `submission.csv` в рабочем каталоге. Расчёт проверен на CPU под Linux (Debian 13), Python 3.12.14.

Тот же расчёт можно запустить из терминала в папке с ноутбуком.

```bash
python - <<'PY'
import json
from pathlib import Path

notebook = json.loads(Path('solution.ipynb').read_text(encoding='utf-8'))
scope = {'__name__': '__main__'}
for cell in notebook['cells']:
    if cell['cell_type'] == 'code':
        exec(compile(''.join(cell['source']), cell['id'], 'exec'), scope)
PY
```

## Данные и модель

В обучающем наборе 31 530 пар для 3 042 запросов. Из них 8 168 пар размечены как релевантные. В тестовом наборе 13 507 пар для 1 305 запросов. Каждый кандидат получает скор.

Из текста убираем HTML, навигацию и скрытые символы. При подготовке текста для Jina исправили кодировку у 106 уникальных фрагментов в train и 61 в test. Пустой заголовок берём из других записей той же статьи, когда он там есть. Jina оценивает запрос и фрагмент с заголовком. На пару отводим 384 токена. У длинного фрагмента сохраняем начало и конец.

Для CatBoost считаем BM25, сходство символьных n-грамм, совпадения в коротких окнах и признаки возможного ответа. Используем также метаданные и сравнения кандидатов внутри запроса и статьи. В числовых полях разбираем пробелы и десятичные запятые, отмечаем пропуски и несогласованные значения. Статистики корпуса считаем по обучающей части каждого разбиения. Признаки на основе разметки для обучающих строк строим по другим компонентам или фолдам.

В CatBoost кандидаты одного запроса образуют группу. Используем QuerySoftMax, 600 деревьев глубины 6 и шаг обучения 0,05. CatBoost и веса объединения обучаем на разметке из `train.csv`. Извне берём готовые веса и токенизатор Jina. `test.csv` используем для прогноза.

Для обучения итогового реранкера выделяем 392 запроса целыми компонентами графа «запрос — фрагмент». Так запросы с общими фрагментами остаются в одной части. Скоры CatBoost для этих запросов получаем после обучения на остальных 2 650 запросах.

Перед объединением центрируем оба скора внутри запроса и делим на стандартное отклонение с нижней границей 0,15. Реранкер учит два неотрицательных веса по парам с разной релевантностью. Используем логистическую функцию потерь, веса пар по изменению NDCG@10 при перестановке и L2-регуляризацию. Получились веса 0,7331 для Jina и 0,2669 для CatBoost. Для прогноза на test переобучаем CatBoost на всём `train.csv`.

## Эксперименты

Сначала проверил оценку отдельных предложений, ядровое ранжирование и признаки позиции кандидата в фоновой коллекции. На двух групповых фолдах выигрыш оказался нестабильным. Затем сравнил готовые реранкеры на небольших выборках.

| Запросы | Локальный NDCG@10 |
|---:|---|
| 16 | Деревья — 0,8845, Qwen3-Reranker-0.6B — 0,8804 |
| 48 | Деревья — 0,8818, Jina — 0,9461, DiTy — 0,7030 |
| 32 из этих 48 | BGE-M3 — 0,9490, Jina — 0,9550, смесь с равными весами — 0,9681 |

В первой полной версии объединил Jina с четырьмя моделями деревьев. Смесь с BGE проверялась на 32 запросах, а полный расчёт с BGE потребовал бы больше времени на CPU.

| Модель в первой полной версии | Все 392 запроса | 344 запроса вне первой проверки |
|---|---:|---:|
| Ансамбль деревьев | 0,8510 | 0,8467 |
| Jina | 0,9559 | 0,9546 |
| Jina и деревья с обученными весами | **0,9578** | **0,9572** |

Это локальная проверка на запросах из `train.csv`. Веса объединения проверял на четырёх фолдах по связным компонентам. Для каждого запроса использовал веса, обученные на остальных фолдах. По сравнению с деревьями NDCG@10 вырос на 0,1068. По парному бутстрэпу компонентов 95%-й интервал прироста — от 0,0901 до 0,1239.

### Замена и добавление CatBoost

Взял те же 421 признак и разбиение на 392 запроса. Проверил замену прежних деревьев, добавление CatBoost с половиной веса в ветке деревьев и добавление с отдельно обученным весом. Скоры перед смешиванием нормировал внутри запроса. Веса объединения с Jina для каждого варианта учил заново на четырёх фолдах по связным компонентам.

| Цель CatBoost | CatBoost отдельно | Вместо деревьев | Половина ветки деревьев | Отдельный вес |
|---|---:|---:|---:|---:|
| YetiRank с NDCG@10 | 0,84404 | 0,95550 | **0,95642** | 0,95482 |
| YetiRankPairwise с NDCG@10 | 0,83544 | 0,95385 | 0,95582 | 0,95369 |
| QuerySoftMax | 0,83695 | **0,95938** | 0,95528 | 0,95502 |

У YetiRank и QuerySoftMax было по 600 деревьев глубины 6. У YetiRankPairwise было 500 деревьев глубины 5 и до 32 границ квантования на признак. Шаг обучения во всех случаях равнялся 0,05. [Цели ранжирования в CatBoost](https://catboost.ai/docs/en/concepts/loss-functions-ranking)

Выбрал замену прежних деревьев на CatBoost с QuerySoftMax. Средний NDCG@10 на 392 запросах вырос с 0,95776 до 0,95938. На 344 запросах вне пилота он вырос с 0,95717 до 0,95851. По парному бутстрэпу компонентов 95%-й интервал прироста составил от −0,00390 до +0,00701.

Сортируем кандидатов по скору по убыванию, при равенстве — по строковому `id` по возрастанию. Дисконт позиции r равен 1 / log₂(1 + r). Для каждого запроса делим DCG@10 на IDCG@10, рассчитанный по идеальному порядку всех его кандидатов. При нулевом IDCG вклад равен нулю. Результат усредняем по запросам.
